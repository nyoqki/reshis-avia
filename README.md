# Решись Авиа · прогноз спроса

Веб-приложение для блока «Разработка» кейса «Динамическое ценообразование авиабилетов» турнира «Решись!».
Авиакомпания из кейса — «Решись Авиа», вылеты из Москвы в пять городов с 1 июня по 1 июля 2026.

Менеджер выбирает направление, дату и цену билета и сразу видит, сколько мест в самолёте, сколько человек захотят
купить билет и сколько купят на самом деле. Рядом — рекомендованная цена с коридором, вероятность того, что места
закончатся, и график распределения спроса.

## Вариант C и четыре дополнительные функции

Выбран вариант C: страница и backend API, который считает. Страница ничего не считает сама, она вызывает
`POST /api/forecast`. Расчёт живёт в `backend/src/rehis/domain/engine.py`, им же пользуется CLI.

| Функция | Где в интерфейсе | Эндпоинты и код |
| --- | --- | --- |
| График распределения спроса | Под карточками результата: 9 сценариев, линия мест, таблица сценариев под графиком | `POST /api/forecast` (поле со сценариями), `frontend/src/features/forecast/ScenarioChart.tsx` |
| Регистрация | Экран входа, вкладка регистрации | `POST /api/auth/register`, `GET /api/auth/options` |
| Авторизация | Экран входа, кнопки «Войти» и «Войти в демо-аккаунт», «Выйти» в шапке | `POST /api/auth/login`, `POST /api/auth/demo`, `POST /api/auth/logout`, `GET /api/me` |
| Хостинг | Живой адрес выше | `Dockerfile`, `compose.prod.yaml`, за обратным прокси (Caddy) на `127.0.0.1:8030` |

Сверху добавлена история расчётов: у каждого пользователя свои последние записи (`GET /api/history`), клик по записи
подставляет маршрут, дату и цену обратно в форму.

## Формулы и округление

Формулы взяты из PDF кейса:

```
желают   = 0.5_base_demand − price_sensitivity × (цена − base_price)
купят    = min(seats, max(0, желают))
свободно = seats − купят
```

- Для графика та же формула применяется к каждому из девяти сценариев с `{q}_base_demand`, q = 0.1…0.9.
- Расчёт идёт в `Decimal`, округление до целых людей — половина от нуля (`ROUND_HALF_UP`). Во `float`
  `0.141 × 3000` даёт `423.00000000000006`.
- «Купят» считается из уже округлённого «желают», поэтому карточки, график и история не расходятся, а медиана графика
  равна «желают».
- Если «желают» получилось отрицательным, интерфейс показывает 0 и рядом сырое значение («расчёт: −3 120»).
- Цена принимается как целое число рублей от 1 до 1 000 000. Цена вне диапазона маршрута не отказ, а предупреждение.
- Вероятность, что места закончатся, считается по девяти сценариям линейной интерполяцией и выводится полосой в
  10 %. Значений «0 %» и «100 %» нет: за пределами 0.1–0.9 распределение неизвестно.
- Рекомендованная цена — `0.5_price`, коридор — от `0.1_price` до `0.9_price`. Если ширина коридора, округлённая до
  целого процента, не меньше 15 % от рекомендованной цены, рейс помечается «рискованный: прогноз неуверенный».

Контрольный пример: Москва → Сочи, 12.06.2026, 9000 ₽ дают 900 мест, 970 желающих и 900 купивших; при 12 000 ₽ —
547 желающих и 547 купивших, свободно 353.

## Данные и подмена на my_forecast.csv

- `data/seasonal_forecast.csv` — заглушка прогноза: 155 строк (5 маршрутов на 31 день), 30 колонок: `route`, `date`,
  `seats` и по три колонки на каждый квантиль 0.1…0.9 (`{q}_base_demand`, `{q}_price`, `{q}_price_demand`).
- `data/routes.csv` — параметры маршрутов: базовая цена, чувствительность к цене, допустимый диапазон цен.

Чтобы подставить собственный прогноз команды в том же формате (допускаются дробные числа), положите его, например, в
`data/my_forecast.csv` и задайте путь:

```bash
REHIS_FORECAST_PATH=data/my_forecast.csv
```

Код менять не нужно. При старте обе таблицы проверяются. Приложение не запустится и напишет в лог файл, строку и
причину, если не хватает колонок, есть лишние или повторяющиеся (маршрут, дата), маршрут не из `routes.csv`,
значение не число или цена `{q}_price` не положительна. В Docker смонтируйте файл в контейнер и раскомментируйте
`REHIS_FORECAST_PATH` и том в `compose.prod.yaml`.

## Быстрый старт локально

Нужны [uv](https://docs.astral.sh/uv/), Node.js и pnpm. Два терминала из корня репозитория.

Терминал 1, backend на порту 8000 (для локального http cookie без флага Secure):

```bash
cd backend
uv sync
REHIS_COOKIE_SECURE=false \
REHIS_DEMO_USERNAME=demo REHIS_DEMO_PASSWORD=<придумайте пароль> \
uv run uvicorn --factory rehis.main:create_app --port 8000
```

Терминал 2, frontend на порту 5173 (запросы `/api` проксируются на 8000):

```bash
cd frontend
pnpm install
pnpm dev
```

Откройте http://localhost:5173. Без `REHIS_DEMO_USERNAME` и `REHIS_DEMO_PASSWORD` кнопки демо-входа не будет, но
можно зарегистрироваться. База создаётся сама в `var/rehis.sqlite3`.

## Быстрый старт в Docker

Образ собирает frontend и запускает backend от непривилегированного пользователя; корень файловой системы только для
чтения, capabilities сброшены, база SQLite лежит на томе `rehis-db`.

```bash
cp .env.example .env
# в .env: REHIS_ALLOWED_HOSTS, REHIS_ALLOWED_ORIGINS, REHIS_DEMO_PASSWORD
docker compose -f compose.prod.yaml up -d --build
```

- Порт публикуется только на `127.0.0.1:8030`; снаружи его отдаёт обратный прокси (Caddy) с TLS. Пример:
  `reshis.example.com { reverse_proxy 127.0.0.1:8030 }`.
- Домены, IP сервера и пароли лежат только в `.env` на сервере, в репозиторий они не попадают. Свой файл
  окружения можно указать через `REHIS_ENV_FILE`.
- Healthcheck ходит с первым хостом из `REHIS_ALLOWED_HOSTS`.

### Проверка IP клиента после деплоя

Лимиты запросов считаются по IP клиента. Адрес берётся из `X-Forwarded-For` только если запрос пришёл от доверенного
прокси из `REHIS_TRUSTED_PROXIES`. В `compose.prod.yaml` это вся закреплённая подсеть `172.30.80.0/24`. Если подсеть
не подходит, все клиенты получат адрес прокси и общий лимит.

После деплоя проверьте, что подсеть сработала: сделайте 11 неудачных входов подряд с одного IP, а затем попробуйте
зайти с другого (например, с телефона). Второй клиент не должен получать 429. Если получает, посмотрите, из какой
подсети приходит запрос (`docker network inspect <сеть>`), и поменяйте подсеть в двух местах
`compose.prod.yaml`: `REHIS_TRUSTED_PROXIES` и `networks.rehis.ipam.config.subnet`. Затем пересоздайте контейнер.

## API

Интерактивная документация OpenAPI открыта на `/docs` (Swagger UI отдаётся самим приложением, без CDN; `/redoc`
выключен).

| Метод и путь | Доступ | Что делает |
| --- | --- | --- |
| `GET /api/health` | открыт | Проверка живости |
| `GET /api/routes` | открыт | Направления, диапазоны цен, даты |
| `GET /api/auth/options` | открыт | Доступны ли регистрация и демо-вход |
| `POST /api/auth/register` | открыт | Регистрация и вход |
| `POST /api/auth/login` | открыт | Вход |
| `POST /api/auth/demo` | открыт | Вход в демо-аккаунт |
| `POST /api/auth/logout` | сессия | Выход |
| `GET /api/me` | сессия | Текущий пользователь |
| `POST /api/forecast` | сессия | Расчёт и запись в историю |
| `GET /api/history` | сессия | Свои расчёты, новые сверху, не больше 50 |

Ошибки приходят с русским текстом; ошибки полей — в `fields.<имя>`. В базе у пользователя хранится не больше 100
последних расчётов.

## CLI

Тот же движок доступен из терминала, без сервера и базы:

```bash
cd backend
uv run rehis-forecast --to Сочи --date 2026-06-12 --price 9000
```

Параметры: `--from` (по умолчанию «Москва»), `--to`, `--date` (YYYY-MM-DD), `--price`. Для контрольного примера
печатает 900 мест, 970 желающих и 900 купивших.

## Демо-доступ

Демо-аккаунт общий и без привилегий: его историю расчётов видят все, кто в него входит, и интерфейс говорит об этом
текстом. Войти можно одной кнопкой «Войти в демо-аккаунт» или вручную:

- имя пользователя: **«ЗАПОЛНИТЬ: имя демо-пользователя»** (по умолчанию `demo`)
- пароль: **«ЗАПОЛНИТЬ: пароль перед сдачей»**

## Безопасность

- Пароли хранятся как argon2id-хеши. В базе лежит только sha256 токена сессии.
- Сессия живёт на сервере. Cookie `rehis_session`: HttpOnly, SameSite=Lax, Secure (кроме локального http), 7 дней.
  Выход удаляет сессию в базе.
- CSRF: POST с чужим `Origin` получает 403, а с телом не в JSON — 415. `Host` вне списка — 400.
- Все ответы, включая ошибки, несут CSP, `X-Content-Type-Options: nosniff`, запрет встраивания во фрейм и
  `Referrer-Policy`; ответы `/api/*` — ещё `Cache-Control: no-store`.
- Лимиты (в памяти одного процесса), ответ 429 с `Retry-After`: вход — 10 попыток за 10 минут на IP и на имя;
  регистрация — 5 в час на IP; демо-вход — 30 за 10 минут на IP; расчёты — 60 в минуту на пользователя.
- Регистрация открыта с потолком `REHIS_MAX_USERS` (1000) и выключателем `REHIS_REGISTRATION_OPEN`; после проверки
  жюри её стоит закрыть.
- На неверный пароль и на несуществующее имя ответ одинаковый. Входные данные проверяет pydantic, лишние поля запрещены.
- Личные данные — только имя пользователя и хеш пароля. Секретов, доменов и IP сервера в репозитории нет.
